# Compiled ZIP acceptance test

Tested September 14, 2026 on the original Apple M1 Pro MacBook Pro, macOS 26.5.2. This was a fresh application data directory on an existing Mac. Rosetta was already installed; a second Mac was not involved.

## Exact artifact

- ZIP: `MapleRoyals-hobby-preview.zip`, 166,069 bytes.
- SHA-256: `3781b97cf769340d5cc91f3cfe1514b6adff8af9f4e41257285a79545fe340ee`.
- Source commit: `c733a8e603132fee3f505efa835ecbf0f219592f`.
- Game installer obtained separately: official `MapleRoyalsSetupWz-02.07.26.exe` (SHA-256 `56fe81f9dd1c1110d4b56c87f468b0955fcf9c27261c411e03b883c7f0d20974`).

The app was extracted from that ZIP. Earlier preview data was preserved under a different directory name, and `~/Library/Application Support/MapleRoyalsLauncher` was confirmed absent before launch. Neither its download cache nor an old Wine prefix was reused. The original working proof of concept was left intact.

## Results

| Stage | Observed result |
|---|---|
| Native first-run UI | Opened; official WZ installer selected through computer use. |
| Runtime provisioning | Downloaded both pinned upstream archives, verified hashes, extracted and completed fresh Wine initialization. |
| Windows installer | User completed it; installer and Wine server wait exited 0. Settings applied and installation marker written. |
| Login and character loading | User reported an initial failure when choosing a character, then successful login and character loading on retry. |
| Movement and map changes | User confirmed changing maps and that it worked well. No frame-time measurements or exhaustive input checks were collected. |
| Runtime and graphics verification | Activity Monitor open-file inspection tied the running game to the fresh prefix and pinned runtime, with builtin `d3d8.dll`, `wined3d.dll`, `opengl32.dll`, `iphlpapi.dll` and Apple's OpenGL renderer loaded. |
| Normal shutdown | Game Wine process exited 0 at 21:44:25 UTC; `wineserver -w` exited 0 at 21:44:29 UTC. Launcher returned to its Play screen. |
| Quit and reopen launcher | Reopened the same extracted app at 21:45:13 UTC. Log records direct `wine C:\MapleRoyals\MapleRoyals.exe` launch, with no repeated download, initialization or installation. |
| Character loading after reopening | Passed: user confirmed the game worked and their character loaded again. |

The first reported failure is unresolved. The initial session log contains a single game launch followed much later by the normal shutdown; it does not identify a separate process crash/relaunch at character selection. We have not established whether this was a process crash, disconnect, or other game error. Successful retry is evidence that gameplay works, not a diagnosed fix for that failure.

## Configuration exercised

The app used `WS12WineCX24.0.7_5` with Template 1.0.15 native libraries, runtime ID `cx24-0.7_5-template-1.0.15`, Rosetta, and a fresh `win64` WoW64 prefix. It ran the unchanged game from `C:\MapleRoyals`.

- WineD3D OpenGL renderer (`renderer=gl`), CSMT DWORD 0, Windows 7 and a 1024×768 Wine virtual desktop.
- `WINEMSYNC=1`, `WINEESYNC=0`, `WINEDEBUG=-all`, `WINEARCH=win64`, `WINEDLLOVERRIDES=mscoree,mshtml=`.
- Explicit per-user `WINEPREFIX`, matching `WINESERVER`, runtime `PATH`, and template Frameworks plus `/usr/lib` in `DYLD_FALLBACK_LIBRARY_PATH`.
- No community `iphlpapi.dll` replacement, DXVK, D9VK or D3DMetal enabled.

The virtual desktop size does not establish the game's internal resolution. That resolution and the physical display refresh rate were not independently recorded during this acceptance session. Earlier performance tests still favor 800×600; this test does not establish smooth 1024×768. The runtime paths and full environment are generated by [PortableCore.swift](../portable/PortableCore.swift); registry defaults are in [settings.reg](../settings.reg).

## Remaining limits

A second Mac, missing-Rosetta installation, Gatekeeper prompts after an actual internet transfer, PIC interaction, long-session stability, sleep/wake and other displays remain untested. Simultaneous clients are unavailable in this launcher. The ZIP is ad-hoc signed without an Apple Developer account or Team Identifier and is not notarized.

The unchanged ZIP remains the tested artifact. These documentation updates do not rebuild it or publish a GitHub release asset. See [recipient instructions](PORTABLE_APP.md) and [third-party notices](../THIRD_PARTY_NOTICES.md).
